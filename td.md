# Техническая документация приложения News Parser

## 1. Общее описание

News Parser — это веб-приложение для агрегирования новостей ведущих московских университетов, их хранения, поиска и отображения в едином интерфейсе. Основная задача системы — регулярно собирать новости с официальных ресурсов университетов, сохранять их в PostgreSQL, а затем предоставлять пользователю удобный доступ через веб-интерфейс, комментарии, поиск и статистику просмотров/лайков.

Система построена по микросервисной схеме на уровне процессов:

- основной веб-сайт (`src/app.py`)
- сервис комментариев (`src/comments_service.py`)
- сервис поиска (`src/search_service.py`)
- сервис статистики (`src/statistics_service.py`)
- краулер новостей (`src/crawler_service.py`)

Все процессы используют общую базу данных PostgreSQL и разные схемы внутри неё.

## 2. Архитектура системы

### 2.1. Компоненты

1. Frontend / Site Service
   - Реализован на Flask.
   - Отвечает за:
     - рендеринг главной страницы
     - загрузку статей по страницам
     - отображение статистики
     - отдачу поискового индекса
     - проксирование запросов к комментариям и статистике
     - отдачу изображений статей
   - Основной файл: `src/app.py`

2. Crawler Service
   - Запускается отдельно как фоновый процесс.
   - Парсит HTML новостных разделов университетов.
   - Извлекает заголовок, текст статьи, дату публикации, изображение.
   - Сохраняет данные в базу и обновляет уже существующие записи.
   - Основной файл: `src/crawler_service.py`

3. Comments Service
   - Отдельный Flask-сервис для хранения комментариев.
   - Позволяет получать комментарии к новости и добавлять новые.
   - Основной файл: `src/comments_service.py`

4. Search Service
   - Обслуживает поисковые запросы по новостям.
   - Запрашивает индекс новостей у основного сайта и фильтрует записи по тексту запроса.
   - Основной файл: `src/search_service.py`

5. Statistics Service
   - Хранит данные о просмотрах и лайках.
   - Поддерживает уникальность просмотров/лайков по `voter_id`.
   - Считает количество комментариев через совместный запрос к схеме `comments`.
   - Основной файл: `src/statistics_service.py`

6. Database Layer
   - Общий слой взаимодействия с PostgreSQL.
   - Инициализирует необходимые схемы и таблицы при первом подключении.
   - Основной файл: `src/database.py`

### 2.2. Схема взаимодействия

```text
Пользователь
   │
   ▼
 Flask Site Service (app.py)
   ├── читает статьи из news.posts
   ├── проксирует /comments/posts/<id>
   ├── проксирует /posts/<id>/view и /like
   ├── обращается к /stats у Statistics Service
   └── отдаёт /api/search-index

Crawler Service ───────► PostgreSQL (schema: news)
Comments Service ───────► PostgreSQL (schema: comments)
Statistics Service ─────► PostgreSQL (schema: statistics)
Search Service ─────────► Site Service /api/search-index
```

## 4. База данных

### 4.1. Общее устройство

В проекте используется PostgreSQL с тремя отдельными схемами:

- `news` — новости и статьи
- `comments` — комментарии пользователей
- `statistics` — просмотры и лайки

Схемы и таблицы создаются автоматически при первом соединении через `initialize_schema()` в `src/database.py`.

### 4.2. Схема `news`

Таблица: `posts`

```sql
CREATE TABLE IF NOT EXISTS posts (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    news_title TEXT NOT NULL,
    news_text TEXT NOT NULL,
    university_name TEXT NOT NULL,
    news_date TEXT NOT NULL,
    news_img BYTEA,
    deleted INTEGER NOT NULL DEFAULT 0
)
```

Назначение полей:

- `id` — идентификатор статьи
- `news_title` — заголовок новости
- `news_text` — полный текст новости
- `university_name` — источник/университет
- `news_date` — дата публикации в формате `DD.MM.YY`
- `news_img` — изображение новости в бинарном виде
- `deleted` — флаг мягкого удаления (`0` — активна, `1` — удалена)

### 4.3. Схема `comments`

Таблица: `comments`

```sql
CREATE TABLE IF NOT EXISTS comments (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    post_id BIGINT NOT NULL,
    nick TEXT NOT NULL,
    text TEXT NOT NULL,
    created_at TEXT NOT NULL
)
```

Назначение:

- `post_id` — ссылка на новость
- `nick` — псевдоним автора комментария
- `text` — текст комментария
- `created_at` — timestamp ISO-8601 в UTC

### 4.4. Схема `statistics`

Таблицы:

```sql
CREATE TABLE IF NOT EXISTS post_views (
    post_id BIGINT NOT NULL,
    voter_id UUID NOT NULL,
    PRIMARY KEY (post_id, voter_id)
)
```

```sql
CREATE TABLE IF NOT EXISTS post_likes (
    post_id BIGINT NOT NULL,
    voter_id UUID NOT NULL,
    PRIMARY KEY (post_id, voter_id)
)
```

Назначение:

- `post_views` — уникальные записи о просмотре статьи конкретным пользователем
- `post_likes` — уникальные записи о лайке статьи конкретным пользователем

Идентификатор `voter_id` передаётся клиентом в запросе и используется для защиты от дублей.

## 5. Основной сайт (`src/app.py`)

### 5.1. Назначение

Основной сайт объединяет пользовательский интерфейс, работу с базой и маршрутизацию запросов к вспомогательным сервисам.

### 5.2. Основные маршруты

#### GET /
- Главная страница сайта.
- Загружает список новостей, сортирует их по дате и визуально выводит карточки новостей.
- При наличии данных статистики отображает количество просмотров, лайков и комментариев.

#### GET /load_articles
- Возвращает JSON со списком статей и признаком `has_more`.
- Используется для пагинации/подгрузки новостей на клиенте.

#### GET /statistics
- Отображает страницу статистики.
- Подсчитывает суммарные значения просмотров, лайков и комментариев.
- Проводит проверку статуса сервисов (comments, search, statistics).

#### GET /api/search-index
- Возвращает массив данных по всем активным новостям.
- Используется сервисом поиска.

#### GET /comments/posts/<post_id>
- Возвращает список комментариев для статьи.

#### POST /comments/posts/<post_id>
- Проксирует новый комментарий к сервису комментариев.

#### POST /posts/<article_id>/view
- Проксирует действие "просмотр" в сервис статистики.

#### POST /posts/<article_id>/like
- Проксирует действие "лайк" в сервис статистики.

#### GET /about
- Страница с информацией о проекте и источниках новостей.

#### GET /article-image/<article_id>
- Возвращает изображение статьи из `posts.news_img`.

#### GET /search-api
- Проксирует поисковый запрос в сервис поиска.

### 5.3. Внутренние механизмы

#### `safe_db_call`
- Обёртка над вызовом к БД.
- В случае ошибки логирует исключение и возвращает безопасное значение вместо падения процесса.

#### `sort_articles_by_date_desc`
- Сортирует новости по дате в порядке убывания.
- При отсутствии корректной даты используется `datetime.min` для стабилизации сортировки.

#### `get_post_stats`
- Делает запросы к сервису статистики для набора `post_id`.
- Если статистика недоступна, сайт продолжает работать, но без числовых показателей.

## 6. Сервис комментариев (`src/comments_service.py`)

### 6.1. Назначение

Сервис хранит и выдаёт комментарии по конкретной новости.

### 6.2. API

#### GET /health
- Возвращает `{"status": "ok"}` при доступности сервиса.

#### GET /posts/<post_id>/comments
- Возвращает массив комментариев в формате:

```json
{
  "comments": [
    {
      "id": 1,
      "nick": "user123",
      "text": "Отличная новость",
      "created_at": "2026-10-06T18:35:00+00:00"
    }
  ]
}
```

#### POST /posts/<post_id>/comments
- Принимает JSON:

```json
{
  "nick": "user123",
  "text": "Новый комментарий"
}
```

- Проверяет:
  - положительный `post_id`
  - корректность типов `nick` и `text`
  - длину полей (`nick <= 40`, `text <= 2000`)
  - непустоту строк после `strip()`
- Создаёт запись в `comments` и возвращает созданный комментарий.

### 6.3. Ограничения

- Комментарии не поддерживают редактирование и удаление через API.
- Сервис работает как отдельный процесс и не связан напрямую с шаблонами Flask.

## 7. Сервис поиска (`src/search_service.py`)

### 7.1. Назначение

Поиск работает поверх индексного массива статей, который формируется основным сайтом. Это позволяет отделить пользовательский поиск от прямой работы с PostgreSQL.

### 7.2. Процесс поиска

1. Получает `q` из query-параметров.
2. Проверяет, что строка не пустая и не превышает `MAX_QUERY_LENGTH = 100`.
3. Запрашивает `NEWS_INDEX_URL` (
   по умолчанию: `http://127.0.0.1:45000/api/search-index`).
4. Проходит по каждому элементу массива и ищет вхождение подстроки без учёта регистра.
5. Возвращает список совпадений до `MAX_RESULTS = 50`.

### 7.3. API

#### GET /health
- Возвращает статус сервиса.

#### GET /search
- Параметр: `q`
- Ответ:

```json
{
  "query": "лаборатория",
  "results": [
    {
      "id": 12,
      "title": "Открылась новая лаборатория",
      "text": "...",
      "name": "МГТУ",
      "date": "05.10.26"
    }
  ]
}
```

### 7.4. Обработка ошибок

- Если индекс недоступен, сервис возвращает `502`.
- Если поисковый запрос слишком длинный, возвращает `400`.

## 8. Сервис статистики (`src/statistics_service.py`)

### 8.1. Назначение

Сервис сохраняет события просмотра и лайка и предоставляет агрегированную статистику по количеству событий на пост.

### 8.2. Важная логика

#### `parse_voter_id(payload)`
- Ожидает `voter_id` в JSON.
- Использует UUID validation.
- Если значение некорректно, возвращает `400`.

#### POST /posts/<post_id>/views
- Добавляет запись в `post_views`.
- Использует `ON CONFLICT DO NOTHING` для дедупликации.
- Возвращает текущее количество просмотров и признак `viewed`.

#### POST /posts/<post_id>/likes
- Добавляет запись в `post_likes`.
- Если пользователь уже ставил лайк, он удаляется (тоггл-логика).
- Возвращает текущее число лайков и признак `liked`.

#### GET /stats
- Принимает несколько `post_id`:

```text
/stats?post_id=1&post_id=2&post_id=3
```

- Возвращает массив статистики по формату:

```json
{
  "stats": [
    {"post_id": 1, "views": 12, "likes": 4, "comments": 5},
    {"post_id": 2, "views": 7, "likes": 1, "comments": 0}
  ]
}
```

- Для подсчёта комментариев сервис проверяет, существует ли схема `comments`, а затем запрашивает `COUNT(*)` по таблице `comments` для нужных `post_id`.

## 9. Краулер новостей (`src/crawler_service.py`)

### 9.1. Назначение

Краулер регулярно обходит официальные новостные разделы университетов, извлекает статьи и сохраняет их в `news.posts`.

### 9.2. Поддерживаемые источники

- МТУСИ: `https://mtuci.ru/about_the_university/news/`
- МАИ: `https://mai.ru/press/news/`
- МГТУ им. Баумана: `https://kf.bmstu.ru/news`
- МИРЭА: `https://www.mirea.ru/news/`

### 9.3. Основные функции

#### `fetch_soup(url)`
- Выполняет HTTP GET с заголовками User-Agent.
- Возвращает DOM в виде BeautifulSoup.

#### `parse_published_date(value)`
- Поддерживает:
  - цифровой формат: `5/10/2026`, `05.10.26`
  - русский формат: `5 октября 2026`, `5 окт 2026`
- Возвращает дату в формате `DD.MM.YY`.

#### `extract_article_text(article)`
- Удаляет `script`, `style`, `noscript`.
- Собирает текст из `p`, `li`, `blockquote`, `h2`...`h6`.
- Удаляет повторяющиеся блоки текста.

#### `NewsDump(currentArticle, title, university_name, img_url, published_date)`
- Проверяет заголовок и содержание статьи.
- Пропускает пустые или невалидные статьи.
- Загружает изображение, если оно доступно.
- Сохраняет запись в `posts`.
- Если статья уже существует, но её текст пустой или усечённый — обновляет содержимое.

### 9.4. Логика дедупликации

Краулер избегает повторных вставок:

- `news_exists(title, university_name)` проверяет наличие статей с тем же `university_name` и тем же заголовком.
- Если новость уже существует, обновляется только дата публикации (`update_existing_news_date`).
- Если текст статьи пустой или слишком короткий, `existing_article_is_empty()` и логика в `NewsDump()` обновляют содержимое.

### 9.5. Планирование

После первого запуска `news_check()` вызывается сразу, а затем по расписанию выполняется каждую час:

```python
schedule.every().hour.do(news_check)
```

Это делает систему полуавтоматическим фоновым обновлением данных.

## 13. Проверки здоровья и мониторинг

Каждый сервис предоставляет endpoint `/health`:

- `site` содержит проверку статуса downstream-сервисов

- `search_service` — `GET /health`

- недоступен

## 14. Безопасность и ограничения

### 14.1. Текущие ограничения

- Сервисы используют простые HTTP-запросы без JWT, авторизации или защитных токенов.
- Основной сайт и сервисы не реализуют rate limiting.
- Поиск и комментарии не проходят через сложную валидацию бизнес-правил, но имеют базовую проверку полей.
- Данные о пользователях не хранятся отдельно; идентификатор `voter_id` передаётся клиентом и служит лишь для дедупликации действий.

### 14.2. Практические замечания

- Для продакшна желательно добавить:
  - TLS / HTTPS
  - аутентификацию и авторизацию
  - более строгий контроль входных данных
  - очереди задач для краулера
  - отдельный мониторинг и логирование в структурированном виде

## 16. Резюме

Приложение представляет собой архитектуру из нескольких Flask-сервисов, объединённых общей PostgreSQL-базой. Основная идея проекта — автоматизировать сбор новостей, хранить их в стандартизированной форме, а затем предоставлять пользователю удобный доступ через веб-интерфейс, поиск, комментарии и статистику.

Ключевые сильные стороны системы:
